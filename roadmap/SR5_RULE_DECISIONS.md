# SR5 Rules Decision Register

This register prevents ambiguous or conflicting text in the approved PDFs from
becoming an accidental implementation decision. `Source-resolved` entries may be
implemented as cited. `Owner decision required` entries block their affected
slice until the project owner records a selection, reviewer, and date.

| `vehicle-modification.manual-operation-absolute-values` | Manual Operation's Availability and cost are printed as relative to its parent mount ("+1" Availability, "+500¥"). | `derived.initiative` | Initiative = (Reaction + Intuition) + 1D6. | `derived.inherent-limits` | Physical Limit = ceil[(Strength x 2 + Body + Reaction) / 3]; Mental Limit = ceil[(Logic x 2 + Intuition + Willpower) / 3]; Social Limit = ceil[(Charisma x 2 + Willpower + Essence) / 3]. | `sr5-core` p. 101 (PDF 103) |
| `derived.condition-monitor` | Physical boxes = ceil(Body / 2) + 8; Stun boxes = ceil(Willpower / 2) + 8; Overflow = Body. Augmentation bonuses to Body/Willpower before rounding are not modeled — no augmentation in the current catalog grants an Attribute-boxes-style Condition Monitor bonus. | `sr5-core` p. 101 (PDF 103) |
| `attribute.karma-overflow` | Physical/Mental attribute points beyond the priority grant are no longer blocked — they draw general creation Karma at the Karma Advancement Table rate: (new rating) x 5 per point, marginally. Free-pool consumption order is alphabetical attribute id (matching the existing canonical-attribute build order). Edge, Magic, and Resonance are excluded — Magic/Resonance increases require Initiation/Submersion, a distinct mechanic not modeled here, so all special attributes stay hard-capped at their metatype/priority grant. | `sr5-core` p. 107 |
| `skill.karma-overflow` | Active Skill points beyond the priority grant cost (new rating) x 2 Karma marginally; Skill Group points cost (new rating) x 5; a specialization beyond the pool costs a flat 7 (shared formula with `knowledge.karma-overflow`). Free-pool consumption order is document array order, individual skills and skill groups tracked against their own separate pools (they are not fungible with each other). | `sr5-core` p. 107 |
| `knowledge.karma-overflow` | Free Knowledge/Language points (Logic + Intuition x 2) cover ranks and specializations 1-for-1 as before. Points beyond that free pool are no longer blocked — they draw general creation Karma at the Karma Advancement Table rate: a rank's marginal cost is its own rank number (rank 1 = 1, rank 2 = 2, ... cumulative 1/3/6/10/15/21 to reach ratings 1-6), and a specialization beyond the free pool costs a flat 7 Karma. Free-pool consumption order is document array order (knowledge entries then language entries, each entry's ranks low-to-high then its specialization). | `sr5-core` p. 107 |
| `identity.license-no-global-legalization` | A license's item/activity type (`identity.fake-license-link`) is recorded as bounded free text (`LicenseSelection.Subject`), not a reference to a specific gear item or a cross-cutting legality flag. `IdentityEvaluator` never reads `Availability.Legality` and returns only a fresh local `CanonicalIdentities` record with no shared/static state, so a license can describe carrying a Forbidden item in flavor text but can never suppress that item's own Availability-12/legality checks elsewhere on the sheet. Resolved as no special-case code — the absence of any cross-reference mechanism between licenses and gear items is itself what satisfies "licenses cannot silently legalize forbidden items." Covered by `Purchasing_a_license_does_not_affect_diagnostics_for_unrelated_items` in `IdentityEvaluatorTests.cs`. | `sr5-core` pp. 419, 443 (PDF 421, 445) |
